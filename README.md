# Project Flow Manager

WPF приложение для управления проектами и задачами с использованием MVVM архитектуры, Entity Framework и SQLite.

## Сборка и запуск

1. Клонируйте репозиторий
2. Откройте решение в Visual Studio 2022+
3. Восстановите NuGet пакеты
4. Запустите приложение (F5)

## Технологии

- .NET 8.0
- WPF
- Entity Framework 6
- SQLite
- xUnit
- Moq

## Структура проекта

### `ProjectFlowManager.Data` - Модели данных и контекст базы данных
- **Models**:
  - `Projects.cs` - модель проекта
  - `Tasks.cs` - модель задачи
- **Entity Framework**:
  - `ModelDB.edmx` - модель Entity Framework
  - `ProjectFlowManagerEntities` - контекст базы данных

### `ProjectFlowManager` - Основное WPF приложение
- **ViewModels** (MVVM паттерн):
  - `BaseViewModel.cs` - базовый класс с INotifyPropertyChanged
  - `MainViewModel.cs` - главная ViewModel со списком проектов
  - `ProjectViewModel.cs` - ViewModel для управления проектом
  - `TaskViewModel.cs` - ViewModel для управления задачей
- **Views** (XAML окна):
  - `MainWindow.xaml` - главное окно приложения
  - `ProjectWindow.xaml` - окно создания/редактирования проекта
  - `AddEditTaskWindow.xaml` - окно создания/редактирования задачи
- **Commands**:
  - `RelayCommands.cs` - реализация ICommand для команд
- **App.xaml** - конфигурация приложения

### `ProjectFlowManager.Tests` - Unit тесты
- **Тесты ViewModel**:
  - `MainViewModelTests.cs` - тесты для MainViewModel
  - Тестируются: инициализация коллекций, свойства, команды
- **Технологии тестирования**:
  - xUnit - фреймворк для модульного тестирования
  - Moq - библиотека для создания mock-объектов

## Особенности архитектуры

1. **MVVM паттерн**: Чёткое разделение на Model, View, ViewModel
2. **Entity Framework**: ORM для работы с SQLite базой данных
3. **Data Binding**: Двусторонняя привязка данных между View и ViewModel
4. **Commands**: Использование RelayCommand для обработки пользовательских действий
5. **ObservableCollection**: Автоматическое обновление UI при изменении коллекций
6. **Dependency Injection**: Контекст базы данных инжектируется в ViewModel

## Основные функции

- Создание, редактирование и удаление проектов
- Управление задачами внутри проектов
- Автоматический расчёт прогресса проекта
- Фильтрация и сортировка задач
- Валидация данных
- Статистика по проектам и задачам

ОТВЕТЫ НА ВОПРОСЫ
1. Связи между сущностями
В базе данных связь организована через внешний ключ ProjectId в таблице Tasks, что соответствует отношению «один ко многим» (один проект — много задач). В коде используется Entity Framework: сущность Projects содержит коллекцию Tasks, а Tasks имеет свойство ProjectId для навигации. Такой подход выбран для удобства ORM, поддержки ленивой загрузки и простоты работы со связанными данными.

2. Расчет прогресса
Логика расчета прогресса проекта находится в методе CalculateProgress() в ProjectViewModel. Она вызывается при загрузке задач, их добавлении, удалении или изменении статуса. Прогресс вычисляется как процент завершённых задач (статус = 4) от общего количества задач в проекте и автоматически обновляется через привязку данных.

3. Управление состоянием
Обновление интерфейса реализовано через механизм INotifyPropertyChanged (реализован в BaseViewModel). При изменении статуса задачи вызывается OnPropertyChanged, что уведомляет WPF-привязки о необходимости обновления. Используется ObservableCollection для автоматического обновления списков в UI.

4. Архитектура
Для добавления системы уведомлений о дедлайнах можно:

Создать сервис NotificationService, который будет периодически проверять задачи с близкими дедлайнами.

Использовать фоновый поток или DispatcherTimer в MainViewModel.

Добавить метод в TaskViewModel для проверки дедлайна и вызова уведомлений через MessageBox или отдельное окно.

Интегрировать вызов этого сервиса при загрузке данных или изменении статуса задачи, чтобы не нарушать текущую MVVM-архитектуру.
